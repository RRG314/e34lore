# E34 Lore Android

Package: `com.e34lore.app`. Canonical origin: `https://e34lore.com`. The owner’s existing Play Console contains a dedicated E34 Lore app with an active internal test. The separate World Explorer app is untouched.

The checked-in `project/` is generated by GoogleChromeLabs Bubblewrap Core 1.27.0, then switches the obsolete JCenter repository to Maven Central. Native sources use the official Android Browser Helper. Target/compile SDK 36, minimum SDK 24, version 0.1.0 / code 1. Android launches the same site and account system in a Trusted Web Activity, falling back to a Custom Tab when domain verification is unavailable.

## Reproduce

Install JDK 21 and the Android SDK, then configure the SDK using an ignored `project/local.properties` or `ANDROID_HOME`. The owner approved the SDK license for E34 compilation. On this Mac, the ignored toolchain is `.codex/android-sdk`; Java is the existing Homebrew OpenJDK 21. Command-line tools 23 are x86-only; the SHA-1-verified official Java-based 21.0 tools work on this arm64 Mac.

```sh
npm ci --prefix android
npm run generate --prefix android
cd android/project
./gradlew --no-daemon :app:bundleRelease :app:assembleDebug
```

Generation serves only local public manifest/icons on a temporary loopback server; no Site token is used or included in generated files. Regeneration must preserve any intended native changes. GitHub CI independently compiles the bundle and debug APK.

The initial native build passed both tasks. The release bundle is unsigned until the E34 upload signing step; debug APKs use Android’s disposable debug signature and must never be registered as the Play upload identity. Exact artifact hashes are in the external release receipt. No emulator/physical-device test is claimed by compilation.

## Signing and website verification

The owner explicitly approved an E34-only encrypted upload keystore at `android/.private/e34-upload.keystore` and password storage in the Mac Keychain service `com.e34lore.android.upload`, account `E34 Lore Android`. The private directory and all key formats are ignored by Git. `scripts/sign-android.mjs` retrieves the password directly into process memory and passes it through environment-based keytool/jarsigner inputs. It never prints or writes the password. The source contains only the public upload-certificate fingerprint. Back up the encrypted keystore and its recovery information through the owner’s normal secure process before production use.

Google Play App Signing is already active for the app. The **app-signing** certificate Google uses on distributed APKs is distinct from the upload certificate. Use its public SHA-256 fingerprint with:

```sh
node scripts/configure-android-links.mjs 'COLON-SEPARATED-PLAY-APP-SIGNING-SHA256'
```

The exact Google-provided certificate and Digital Asset Links JSON have now been captured in play-signing-certificate.json and public/.well-known/assetlinks.json. Publish the resulting `/.well-known/assetlinks.json` on the exact launch origin without redirects/authentication, then verify on a real device. The Site’s owner-private gate currently prevents anonymous Digital Asset Links verification; this is a public-launch dependency, not something to bypass with a secret in the app. No secret, service credential, keystore or private manual belongs in Android assets.

The compiled app uses the PWA manifest and online functionality. Its offline behavior is a reconnect page, with no private page caching or offline writes. Release notes must not promise offline repair access or unimplemented uploads.

## Physical verification checklist

Use the existing E34 Lore internal Play track and an allowlisted Google account on an authorized physical Android device. Keep package `com.e34lore.app`, version code and signing identities tied to the Play record. The website updates inside the existing trusted web activity.

1. Install via Play, open cold and verify that the trusted activity opens the canonical website without an unexpected address bar. Compare [the association file](https://e34lore.com/.well-known/assetlinks.json) with the Play app signing certificate.
2. Use portrait, landscape, enlarged font and TalkBack. Verify labels and focus order for navigation, search, a fuse, an OEM position, a guide step and the moderation gate. Test the Android back gesture and linked chapter/step anchors.
3. With authorized accounts, test email and Google return, session persistence, private garage and journal isolation, explicit photo publication and logout. For uploads, verify the file picker, denial of unsupported files and image controls.
4. Verify public link opening, external browser handoff, share sheet, copy link and return. Test a cold start without connectivity and recovery once online.
5. Record device model, Android/Chrome versions, Play version code, build source, pass/fail steps and cleanup. Keep emails, tokens and private records out of screenshots.
