## Usernames and owner moderation

`profiles.username` is unique and lowercase: 3–24 ASCII letters/numbers/underscores, starting with a letter. Reserved staff/service handles are rejected. Members choose a permanent handle after authentication. `claim_username` serializes first claims, rejects collisions and synchronizes the existing `display_name` author field, so discussions/garages/helpful comments use the chosen handle without an email fallback. Direct client profile writes are revoked. The existing bio column is preserved. No Google name/email is copied automatically into a public profile. The account page alone displays the signed-in user's email.

The owner's supplied moderator address is held only in `e34_private.owner_account_claim`. The previous member-callable activation functions have been removed. A privileged migration bound the already verified owner Auth UUID and assigned its moderator role. No profile, metadata, typed email or public endpoint can assign staff access. The binding cannot silently move to a replacement identity. Deliberate operator administration is required for future staff assignments or recovery. The owner chose the verified owner and completed authenticator verification on 7 November 2026; the actual staff dashboard and community moderation loaded. Moderation requires the private role plus MFA. See [guest access and operations](guest-access-and-operations.md).

Private implementations use the established fixed-search-path security-definer boundary in `e34_private`; public RPC facades are security invokers. The owner table has explicit deny policies and no client table grants. Existing moderation actions retain their separate role and MFA checks. Account settings can revoke other devices' refresh sessions. Existing JWTs remain valid until expiry; the UI discloses this. Password recovery also revokes other refresh sessions after the password is saved. Account deletion retains fresh Auth validation and session revocation.

## Public links

`ShareControls` provides native Web Share when supported, a Copy link button, selectable fallback and user-initiated email composition. Canonical links always use `https://e34lore.com`. Page-intro controls cover the existing public reference/community/garage pages. Replies have direct thread/reply links. Guide steps include immutable revision plus step anchor. Published journal updates have a focused lookup so older entries outside the initial page are reachable.

A route and query allowlist excludes account, private garage, draft composer, staff and callback routes. Auth tokens, callback codes, return URLs and unrecognized parameters/hashes are stripped. Catalog context, assembly, position and part selections remain shareable. Private journal editing has no public-share control; members must explicitly publish through the existing review/snapshot flow. Links do not override withdrawal, reports, hidden states or RLS. Previously shared links may therefore become unavailable.
