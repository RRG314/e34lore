# E34 / M50 digital-twin asset and reconstruction research

Research date: 2026-11-05. Scope: initial 1995 BMW E34 525i, M50 family, full XYZ component inspection. Build date, market, body, transmission, engine variant and modifications still need to identify the actual reference vehicle. This report does not assign part compatibility from a model title.

The bounded search established **one reusable existing E34 visual asset family and one licensed standard-fastener data library**. It did **not** establish a redistributable, dimensionally validated 1995 E34 engine bay, complete M50TU engine, or all internal/hardware geometry. The interactive platform can support those assets as they are acquired; software interaction capability and geometric completeness are separate release criteria.

`asset-inventory.json` contains 12 records, explicit eligibility states, source and download-page URLs, unknown fields represented by null, saved metadata evidence, local hashes, accuracy qualifications and segmentation findings. `licensed-fastener-tables/PROVENANCE.json` records five staged tables against immutable repository commit `a57bb7a24762d367d66369f280a24c38a64e73dd`.

## Reconstruction method supported by primary documentation

| Tool | Useful role | Limits / license evidence |
|---|---|---|
| COLMAP | Multi-view photographs → camera poses/sparse points → dense surface. Capture textured objects with overlapping views under consistent lighting; move around them. | Shiny castings, featureless plastic and inaccessible surfaces are difficult. No output alone certifies scale or accuracy. Its tutorial recommends each subject appear in at least three images. BSD-3-Clause software; dependency licenses remain separate. [Tutorial](https://colmap.github.io/tutorial.html), [meshing limits](https://colmap.github.io/faq.html#surface-mesh-reconstruction), [license](https://github.com/colmap/colmap/blob/main/LICENSE). |
| Open3D | RGB-D integration, registration, point-cloud filtering, geometry inspection and surface reconstruction. | Poisson meshing can extrapolate beyond observed points; low-density triangles are evidence of weak support, not newly measured surfaces. Keep those regions flagged or excluded. MIT software. [Pipeline](https://www.open3d.org/docs/latest/tutorial/reconstruction_system/index.html), [surface reconstruction](https://www.open3d.org/docs/latest/tutorial/geometry/surface_reconstruction.html), [license](https://github.com/isl-org/Open3D/blob/main/LICENSE). |
| FreeCAD | Reconstruct measured interfaces as parametric solids; retain dimensions, constraints, datum frames and editable history; export STEP as an engineering master. | BRep/NURBS and precise units represent supplied measurements; they cannot make guessed dimensions accurate. Default code license is LGPL-2.1-or-later; individual files/dependencies vary. [Capabilities](https://freecad.github.io/Website/features/), [copyright](https://freecad.github.io/Website/dev/code/copyright/). |
| Blender | Segmentation, cleanup, retopology, UV/material work and lightweight glTF/GLB scene export. | Use distinct component objects and persistent IDs; do not weld an engine into one unselectable shell. Retopology/decimation can erase small interfaces. GPL application; owned output artwork is not automatically GPL, while borrowed asset licenses persist. [Export custom properties](https://docs.blender.org/manual/id/5.0/addons/import_export/scene_gltf2.html), [output licensing](https://www.blender.org/about/license/). |

Single-image tools are unsuitable as measurement evidence. [TripoSR](https://github.com/VAST-AI-Research/TripoSR) provides an MIT-licensed single-image reconstruction implementation; no code or weights were executed/downloaded. [Zero-1-to-3](https://zero123.cs.columbia.edu/) explicitly describes an underconstrained problem solved using learned geometric priors. Generated views can be attractive and mutually consistent without matching an actual component.

**Geometric inference:** one exploded drawing cannot uniquely specify XYZ shape. Multiple solids can produce the same projection. An exploded illustration also offsets components for legibility and lacks a calibrated capture geometry. It can establish visible callouts, association and assembly order where explicit; it cannot establish unseen back faces, wall thickness, galleries, locating shoulders, clearances, thread engagement or tolerances. Neither AI generation nor mesh hole-filling supplies missing measurement evidence. Even photographs from every accessible exterior angle leave internal/occluded geometry unresolved. That requires disassembly/direct measurement, trustworthy dimensioned sources, or suitable internal imaging.

## Practical acquisition and integration sequence

1. Fix the reference configuration: build date/market/body/transmission, engine identity and physical part markings, options and modifications. Resolve substitutions against the owned factual catalog; keep a relationship unconfirmed when evidence is absent.
2. Capture the assembled engine bay for location and routing, with calibrated scale references and a declared vehicle datum frame. Record access limitations before disassembly. Capture each removed component around all accessible sides; maintain an immutable raw photo/scan set, creator/permission record, calibration information and physical check dimensions. A phone depth scan can supply an envelope, but its sensor resolution is not a thread/interface tolerance certificate.
3. Rebuild critical mating interfaces from direct measurements in CAD. Store the measured values, method, tolerance/uncertainty and checkpoints per part. Establish inaccessible internals separately; do not infer unseen channels, bolt lengths or wall thickness from a silhouette. Review total assembly alignment against independent check measurements rather than the same points used to fit it.
4. Maintain a source master and a runtime asset. Each component needs a stable geometry ID, assembly-instance ID, catalog relationship/evidence, parent, assembled transform, pivot, optional joint/axis and reversible display-only explode transform. Include washers, clips, gaskets and fastener instances only when actually identified. Reuse identical hardware meshes while preserving distinct instance records.
5. Export named GLB nodes with IDs in `extras`; test round trips and assert unique IDs instead of relying on display names. glTF distances are meters, while engineering CAD commonly uses millimeters: record/test the conversion and axis transform explicitly. [Khronos glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html). Retain original high-resolution masters; stream subassemblies and inspection LODs, and confirm close-up legibility against visual and dimensional checkpoints.
6. Show evidence per component: illustrative, scanned surface, measured envelope, measured interfaces, internally verified. Keep unknown regions visible in coverage metadata. Define an acceptance tolerance appropriate to each intended use; do not publish one global accuracy number or imply the whole vehicle is complete because it rotates in XYZ. A display cut plane exposes mesh geometry; it does not verify material thickness or internal topology.

Suggested minimum component evidence record: `geometryId`, `instanceId`, `partRelation`, `configuration`, `source`, `license`, `sourceHash`, `geometryMethod`, `units`, `datumFrame`, `transform`, `measuredChecks[]`, `uncertainty`, `observedSurfaces`, `inferredRegions`, `coverage`, `reviewStatus`. Missing values stay unknown. A generic nominal bolt must remain distinct from a confirmed OEM bolt instance.

The next asset dependency is an owned/permissioned, segmented M50TU cooling/front-accessory assembly with actual E34 mounting/routing evidence. No available research result yet supports declaring all cooling components, fasteners, internals or repair clearances complete. This is an asset release dependency, not a reason to replace completed catalog, community or diagnostic implementations.

## Research boundaries and validation

No application source or database was changed. No model archive was downloaded, no third-party code executed, and no signup/payment/access bypass attempted. Existing local GLB JSON headers/mesh structure were inspected as data. Primary public Sketchfab Data API metadata was used where normal web pages were inaccessible; no hidden viewer geometry was extracted. All five staged fastener tables were re-fetched at the recorded immutable commit and their SHA-256 hashes matched. Six small license/documentation snapshots are retained alongside source metadata. These research files are private working evidence, not public model assets.
