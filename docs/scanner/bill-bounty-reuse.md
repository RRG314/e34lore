## Actual implementation

The current implementation is a custom browser capture/preprocessing/OCR interface plus an optional server-side Gemini currency reader. It is not a specialized trained object detector, segmenter or image-embedding retrieval system. Client OCR and server image upload/vision run concurrently. There is no live neural inference on video frames.

## Coupling and extraction cost

The useful camera, JPEG and pixel-array routines are embedded in a large currency modal, not exported as a maintained library. Copying the complete modal would also import Next navigation, form DOM mutation, registry/hunt types, bill ratios, currency parsers, geolocation, uploads and analytics. A small E34-owned camera controller plus pure preprocessing helpers is the lower-coupling option. Track this SHA and source functions in copied-file comments and tests. There is no reason to make either project depend on the other’s deploy or production API.

Additional work required around these algorithms: camera generations/abort semantics, image object URL cleanup (preprocessing URLs are revoked, but preview URL allocation at modal line1203 has no matching preview revocation), file/decode/dimension caps, unsupported camera fallback, genuine focus/blur/exposure metrics, mobile torch/zoom capability checks, selected-region crop/rotation, multiple-angle evidence, model progress/worker termination, bounded caches, owner-account changes and authenticated private persistence. The original source is useful evidence of UI patterns, not a complete secure reusable scanning SDK.

## Tests and verification limits

`tests/unit/bill-scanner.test.ts` verifies currency text parsing and assembled warnings using provided text strings. It does not execute actual OCR/model inference against held-out photographs. Other source tests cover rate limiting and privacy utilities, but no camera permission/lifecycle, crop-coordinate, OCR-worker cancellation or real-photo recognition benchmark was found. The existing Playwright `tests/e2e/dollar-game.spec.ts` does not establish hardware scanning accuracy. No Bill Bounty test suite or server was executed during this read-only audit.

No actual mobile camera, iOS/Android device, Gemini credential, production image, Bill Bounty live deployment setting or backend data was inspected. No recognition accuracy, latency, memory, offline compatibility or production deployment identity can be certified from source alone. E34 needs its own isolated synthetic camera tests and genuine held-out automotive inference evaluation; synthetic camera input is not hardware certification.

**Do not run Bill Bounty’s `npm run build` as a casual audit step:** the inspected script executes `prisma db push --accept-data-loss` before `next build`. This audit ran neither build nor migration commands and read no `.env`/credential files. Reference `git status --porcelain` was empty after inspection.
