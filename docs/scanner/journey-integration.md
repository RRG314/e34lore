# Scanner, catalog, walkthrough and garage continuity

8 November 2026. Baseline `d8ca5fa76c1039833d3449dcaf346d97d08f4525`, live Site40. Branch `steven/scanner-repair-journeys` extends the working scanner and repair implementation; it does not replace the viewer, canonical catalog, journals or garages.

## Connected behavior

The header vehicle picker can select an actual garage car. One shared owned-car query serves the application, with a 12-second timeout, explicit owner scope and a 100-car bound. Selected private car IDs stay in account-scoped session storage and validated navigation context. A foreign or unavailable requested car never silently falls back to another owned car. General reference selection remains available without creating a garage record. Supported configuration fields enter the existing fitment/guide context; uncertain installed engines, production month and market remain unknown.

Scanner confirmations open the exact canonical catalog while preserving the selected car and saved identification. Canonical BMW IDs and existing curated aliases share the source-backed procedure resolver. An M20 pump number does not acquire the M50 pump procedure merely because both are water pumps. Catalog browsing keeps context when changing an assembly/position. Readable markings, source conditions and owner confirmation remain separate from fitment and visual similarity.

The garage's new Identifications tab reuses the same private history component as the scanner: actual part names/BMW numbers, car, date, notes, source catalog, related procedures, individual correction drafts and deletion. A 30-record cursor page includes timestamp/id tie handling. Category-only observations retain their uncertainty and never become an OEM identity automatically. Saved scans are checked against both current account and selected car before they can link to progress; deleted/foreign/other-car identifiers show an error and can be explicitly dropped.

Written guide checks and interactive operations reuse the existing `guide_progress`. Once a source-pinned interactive plan is attached, the written page derives its checked stages from completed operations and directs operation changes to that plan. It cannot overwrite operation progress through the generic checklist controls. The interactive page retains original scan/configuration references, can prefill a saved canonical part for explicit parts-used confirmation and returns to the correct car's progress. Repair state remounts on account/car changes. The garage opens the exact saved guide revision or current matching interactive plan and displays retained completed-run parts and private service/journal links.

The add-car form now records body style and transmission without a second edit, and starts unspecified configuration fields empty instead of inheriting another selected car's market/body/transmission. All existing photos, maintenance, modifications, publication and withdrawal controls remain.
